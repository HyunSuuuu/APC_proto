## 1. 목표

- [확인](또는 자동 확인)을 누르면, 영수증이 **절취선을 따라 왼쪽에서 오른쪽으로 '드-드-드-득' 끊기며** 떨어져 나간다.
- 샘플에서 **종이가 심하게 뒤틀려 메시가 접히고 깨지던 부분은 없앤다** → 어떤 값을 넣어도 삼각형이 뒤집히지 않아야 한다 (3절).
- 지금 있는 출력 연출(줄마다 밀려 나옴 · 윗부분 말림 · 도장 · 카운트다운)은 그대로 둔다.

## 2. 현재 구조와 샘플의 차이

| | 샘플 HTML | 우리 게임 (지금) |
|---|---|---|
| 출력기 위치 | 위 | **아래** (종이가 배출구에서 위로 올라옴) |
| 절취선 | 배출구 바로 아래 | → **배출구 바로 위**로 옮김 |
| 뜯긴 종이 | 왼쪽이 아래로 처지다 떨어짐 | → **왼쪽이 위로 들리고**, 다 끊기면 **위로 날아감** (지금의 퇴장 방향 유지) |
| 남은 조각(Stub) | 위로 수납 | → 배출구 안(**아래**)으로 수납 |
| 종이 메시 | 28×36 격자 | `ReceiptPaperGraphic` = 세로는 띠로 나눴지만 **가로는 4칸뿐** → 가로 분할을 더해야 함 |
| 글씨 | 텍스처에 함께 그림 | TMP · Image가 따로 있음 → `ReceiptCurlVertex`가 같은 변형 함수를 적용 |

즉 샘플을 **위아래로 뒤집어(y 반전)** 적용한다. 회전 방향도 반대가 된다: 샘플은 왼쪽이 아래로, 우리는 왼쪽이 위로 간다.

```
        ┌──────────────┐  ← 윗부분은 지금처럼 뒤로 말림 (ReceiptCurl, 유지)
        │  DAY N       │
        │  수익 ...    │
        │  순수익 [도장]│
        │  뜯기 안내    │
  ◀ ─ ─ ┼ ─ ─ ─ ─ ─ ─ ─┼ ─ ▶  ← 절취선 (perfY) — 새로 그림
        │   Stub       │  ← 남는 조각 (높이 stubHeight)
   ═════╧══════════════╧═════  ← 배출구 틈 (마스크 아래 끝)
        [   출력기 몸체   ]
```

## 3. 샘플이 깨지는 원인과 해결

### 3.1 원인 (샘플 코드 분석)

1. **좁은 구간에서 큰 회전을 섞음 (가장 큰 원인)**
   TEAR 단계에서 `lerp(원래 위치, 회전한 위치, tornMask)`를 쓰는데, `tornMask`가 바뀌는 폭은 종이 너비의 6.5%뿐이다. 그런데 회전축에서 멀리 떨어진 종이 아래쪽은 회전 때문에 최대 약 150px나 움직인다. 바로 옆 열끼리 위치가 150px씩 차이 나니 **삼각형이 뒤집혀(접혀) 겹친다**. 이것이 "너무 뒤집어서 깨지는" 모습이다.
2. **주름 변위가 격자 간격보다 큼**
   `bendInwardX`(최대 18px)와 `ridgeWave × buckleAmp`(최대 약 8px)가 절취점 근처의 작은 삼각형(간격 약 9px)보다 크게 움직여서, 작은 삼각형이 뒤집힌다.
3. **단계가 바뀔 때 변형 공식이 통째로 바뀜**
   TEAR와 DROP은 주름 함수가 서로 다르다. 그래서 TEAR가 끝나는 프레임에 주름이 순간적으로 바뀌며 튄다.

### 3.2 해결 원칙

| # | 방법 | 효과 |
|---|---|---|
| A | **뜯긴 몸통 전체를 하나로 회전**한다. 좁은 구간에서 섞지 않는다. 아직 붙어 있는 오른쪽은 **절취선 근처 세로 구간(`bendHeight`)에서만** 원래 자리에 묶어 두고 위로 갈수록 몸통 회전에 합류시킨다 | 큰 이동이 넓은 구간에 퍼져서 접히지 않음 |
| B | **각도 상한을 자동으로 정한다**: `남은 오른쪽 길이 × sin θ ≤ 0.5 × bendHeight`. 오른쪽이 아직 많이 붙어 있을 때는 조금만 들리고, 다 끊길수록 많이 들린다 | 묶인 부분과 회전한 부분이 겹치지 않음 |
| C | 주름은 **음영(Vertex Color) 위주**로 표현한다. 위치 변위는 `격자 간격 × 0.25` 이하로 제한 | 작은 삼각형이 뒤집히지 않음 |
| D | **변형 함수를 하나로** 만든다. 날아가기(FLY)는 'tearU = 1인 TEAR 상태' 위에 이동 · 회전만 더하고, 주름은 `relax` 배율로 서서히 줄인다 | 단계가 바뀔 때 튀지 않음 |
| E | **접힘 방지 가드**: 매 프레임 거친 격자(12×16)로 변형 결과의 야코비안 행렬식(삼각형 넓이 비율)을 계산한다. 최솟값이 `0.3`보다 작으면 변형 세기(`amount`)를 이분 탐색(3회)으로 줄인다. 같은 `amount`를 종이 · 글씨 · 아이콘에 똑같이 적용 | 값을 잘못 넣어도 절대 깨지지 않음 (최후의 안전장치) |
| F | 뒤집기(z 방향 뒤집힘 · 뒷면 노출)는 하지 않는다. 화면 평면 안의 회전(최대 약 25°)과 기울기만 쓴다 | 뒷면 처리 불필요. 윗부분 말림(`ReceiptCurl`)의 뒤집힘은 원래 의도한 것이므로 그대로 둔다 |

## 4. 연출 타임라인 (샘플의 1.5배 빠른 템포 유지)

| 단계 | 시간 `임시` | 동작 |
|---|---|---|
| 0. 준비 | 출력 끝날 때 | 마지막 줄 다음에 `stubMargin`만큼 더 밀어내서 절취선이 글씨 아래 빈 여백에 오게 한다. 절취선(점선 + 양옆 삼각 노치)이 0.15초 동안 나타난다 |
| 1. 예비동작 (ANTICIPATE) | 0.12초 | 왼쪽 아래 모서리가 살짝 위 · 왼쪽으로 당겨진다 (OutCubic). 대각선 초기 주름은 음영만 |
| 2. 뜯기 (TEAR) | 0.48초 | `tearU` 0→1을 **8단계 계단형**으로 진행 (샘플 `steppedZipper` 그대로). 회전축 = (절취 지점 x, perfY). 몸통이 시계 방향으로 들린다 (θ = θ0 + θ1·tearU, 3.2 B 상한 적용). 단계마다 **화면(팝업 Body 전체)을 짧게 흔든다** (`stepShake` 5, 0.1초). 파티클은 없음 `확정` |
| 3. 날아가기 (FLY) | 0.42초 | 마지막으로 끊기는 순간 화면을 크게 흔들고(`snapShake` 16, 0.28초) 출력기를 아래로 툭 친다. 다 끊긴 몸통이 오른쪽 끝을 축으로 θ에서 조금 더 돌며 위로 날아간다 (InCubic, 오른쪽으로 살짝 흐름). 58% 지점부터 페이드. 주름은 `relax = exp(-4.5t)`로 펴진다 |
| 3'. 남은 조각 수납 | 0.12초 후 0.26초 | 남은 조각이 톱니 단면을 0.12초 보여 준 뒤, 배출구 안으로 내려간다 (InOutCubic, 기존 마스크가 자름) |
| 4. 마무리 | 지금과 같음 | 출력기 내려감 + 배경 밝아짐 → `PartService.Confirm` |

- 총 길이: 지금 약 0.6초 → **약 1.0초** (+ 출력기 퇴장 0.35초).
- 팝업이 게임 시간을 멈추므로 모두 `SetUpdate(true)`로 돈다.

## 5. 구현 설계

### 5.1 새 컴포넌트 `ReceiptTear` (`Scripts/UI/ReceiptTear.cs`, 종이 루트에 `ReceiptCurl`과 함께)

- **상태 값**: `phase`(Idle · Anticipate · Tear · Fly), `anticipate`, `tearU`, `fly`, `stubRetract`, `amount`(가드가 정하는 0~1).
- **기하 값**: `perfY`(종이 로컬 y, 배출구 마스크 위 끝을 종이 좌표로 바꾼 값 + `stubHeight`), `paperRect`.
- `Vector3 Deform(Vector3 p, out float shade, out bool isStub)` — 3절 A~D를 하나의 함수로 처리한다. `p.y < perfY`이면 Stub이고 수납 이동만 한다.
- `Play(Action onComplete)` — 1~3' 단계를 DOTween `Sequence`로 실행한다. 값을 바꾼 뒤 `LateUpdate`에서 가드(E)를 계산한다.
- 변형 순서: **말림(`ReceiptCurl.Deform`) → 뜯기(`ReceiptTear.Deform`)**. 말림은 위쪽, 뜯기는 회전 · 아래쪽을 맡으므로 서로 부딪치지 않는다.

### 5.2 고칠 기존 스크립트

| 파일 | 바뀌는 점 |
|---|---|
| `ReceiptPaperGraphic` | ① 절취선 위아래 `bendHeight` 구간을 가로 `perforationPitch`(약 12) 간격 열 × 세로 8 간격 띠로 잘게 나눈다 (나머지 위쪽은 지금처럼 4열). ② perfY 줄의 정점을 **두 벌**(Stub용 · 몸통용) 만들어 실제로 떨어질 수 있게 한다. ③ 뜯긴 구간만 톱니 단면(±1.5, `smoothstep`으로 연속)을 보인다. ④ 점선(안 뜯긴 구간만) · 양옆 노치 · 뜯긴 단면 테두리를 같은 메시에 그린다. ⑤ 정점마다 말림 다음에 뜯기 변형을 적용한다 |
| `ReceiptCurlVertex` | `DeformVertex`: 말림 구역 밖이어도 뜯기가 동작 중이면 `ReceiptTear.Deform`을 적용하고, 음영을 곱한다. (씬 참조가 깨지지 않게 이름은 그대로 둔다) |
| `ReceiptCurl` | `LateUpdate`: 뜯기가 동작 중이면 위쪽 구간만이 아니라 **모든** 자식 그래픽을 갱신한다 (약 1초, TMP 약 20개라 부담 적음) |
| `SettlementPopup` | `FinishPrinting`: `stubMargin`만큼 더 밀어내고 절취선을 보인다. `Confirm`: 지금의 위로 날아가기 Tween을 **`ReceiptTear.Play` → 출력기 · 배경 퇴장**으로 바꾼다. `tearCurlDegrees`(뜯을 때 더 말림)는 TEAR 동안 그대로 쓴다 |

### 5.3 입력 · 타격감 (2026-11-23 결정)

- **어디를 눌러도 뜯긴다** `확정`: 배경(Dim) · 종이 · 출력기 · [확인] 어디든 누르면 `Confirm`. 출력 중에 누르면 지금처럼 바로 다 나온 상태가 되고, 다음 터치에 뜯긴다. `SettlementPopup`이 `IPointerClickHandler`를 구현해서 처리기가 없는 그래픽(출력기 이미지 · 글씨)을 누르면 이벤트가 위로 올라와 받는다. 종이는 `ReceiptPaperGraphic.Clicked`, 배경은 `dim.onClick`으로 받는다.
- **화면 흔들림** `확정` (파티클 대신): 팝업 `Body`를 흔든다 (단계마다 약하게, 마지막에 강하게). 흔들 때 화면 가장자리가 드러나지 않게 Dim을 사방 80만큼 넓힌다.
- 효과음: 프로젝트에 사운드 시스템이 아직 없어서 넣지 않는다.
- 마스크(`PaperViewport`, RectMask2D) 폭이 600이라 기운 종이가 잘린다 → 실행할 때 폭을 1600으로 넓힌다 (세로는 그대로라 배출구 아래는 계속 가려짐).

### 5.4 조정 값 (인스펙터, `임시`)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `stubHeight` | 26 | 배출구와 절취선 사이 남는 조각 높이 |
| `stubMargin` | 40 | 출력이 끝난 뒤 더 밀어낼 길이 (글씨가 절취선에 걸리지 않게) |
| `bendHeight` | 140 | 붙어 있는 오른쪽이 휘는 세로 구간 |
| `perforationPitch` | 12 | 절취선 구멍 간격 = 아래 구간 가로 분할 간격 |
| `anticipateDuration` / `tearDuration` / `flyDuration` | 0.12 / 0.48 / 0.42 | 단계별 시간 |
| `tearSteps` | 8 | '드-드-드-득' 단계 수 |
| `tearAngle` | 12° | 다 뜯겼을 때 들림 각도. 뜯긴 비율만큼 0°부터 커진다 (3.2 B 상한이 우선). **바뀜**: 6° → 22° 안 → 종이가 906으로 길어서 위 끝이 너무 많이 쏠려 0 → 12° |
| `flyHeight` | 1100 | 날아가는 거리 |
| `creaseShade` | 0.11 | 대각선 주름 음영 세기 |
| `minJacobian` | 0.3 | 접힘 방지 가드 기준 |
| `debugSpeed` | 1 | 확인용 배속 (0.35 = 샘플의 슬로우모션) |

## 6. 작업 순서

1. `ReceiptTear` 변형 함수와 가드 작성 + `ReceiptPaperGraphic` 메시 분할(절취선 · Stub 분리)
2. `ReceiptCurlVertex` · `ReceiptCurl` 연동 (글씨 · 아이콘이 종이와 함께 움직이는지)
3. `SettlementPopup` 연결 (준비 → 뜯기 → 퇴장)
4. (선택) 섬유 파티클 · 종이 클릭으로 뜯기
5. Play 테스트: `End Part` ×2 → 정산 → [확인] · 자동 확인 · 출력 중 [확인]. `debugSpeed 0.35`로 프레임마다 접힘이나 틈이 없는지, 단계가 바뀔 때 튀지 않는지, 미지급 알바 줄이 있을 때(종이가 길 때)와 없을 때를 모두 확인
6. 문서 갱신: CheckList · Wiki(4.x `ReceiptTear` 항목, `SettlementPopup` 갱신) · GDD 9.5 연출 문단
