## 인수인계 — 이어받은 사람이 할 일 (2026-11-11 기준)

**현재 상태**: M0~M5 · M5b · M7 완료, M6 절반 (M6-1~4, 4/8), M8 절반 (57/78). 혼자서 계약 → 하차 → 분류 → 피킹 → 상차 → 현금 → 저금통 → 파트 정산 사이클이 돈다. 알바 3명(하차 · 분류 · 피킹)도 디버그 메뉴로 만들면 손을 놓아도 돈다 (고용 데스크 전). 레벨로 구역이 자동 해금된다 (Lv.3 선반 B · Lv.5 하차장 3 · Lv.7 상차장 3 · Lv.11 반품).

### 1. 시작하기 전에
1. 저장소를 받고 `git lfs install` → `git lfs pull` (폰트 에셋이 LFS)
2. Unity **6000.3.26f1**로 연다. 처음 열 때 TechStack 3절 확인 (R3 NuGet DLL은 `Assets/Packages`에 커밋돼 있음)
3. `Assets/Scenes/Game.unity`를 열고 Play. F1 또는 왼쪽 아래 `DEBUG`로 치트 메뉴 (현금 · 레벨업 · 배속 · 주문 추가 · `End Part` · 모듈 해금)
4. 씬 · 프리팹이 이상하면 메뉴 `APC > Setup > Build Site` (Site · HUD를 지우고 다시 만듦). 배치 · 레벨 표까지 기본값으로 되돌리려면 `APC > Setup > Apply Layout v0.3` (config 값을 덮어씀 — 이후 v0.4 값은 [M5b 데이터](#m5b-저금통--파트-정산-gdd-76-91-95--v04-신규) 줄 참고해 다시 넣어야 함)
5. 문서를 먼저 읽는다: [GDD](GDD.md) v0.4 (무엇을) → [Wiki](Wiki.md) (코드가 어떻게) → [TechStack](TechStack.md) (도구 · 규칙)

### 2. 다음 작업: **M6-5 고용 데스크** (M6 절, 8개 중 M6-1~4 완료)
- 순서 제안: M6-5 고용 데스크 → M6-6 배치 현황판 → M6-7 시급 → M6-8 밀린 시급
- 이미 준비된 것:
  - 네비메시: `SiteNavMesh`가 열린 모듈 바닥에만 굽고 해금마다 다시 굽는다. 선반은 M6-1에서 `NavMeshObstacle`로 장애물 처리 완료 (트럭은 부지 밖 주차라 처리 안 함)
  - 수요 예약: `OrderService.Reserve` / `Unreserve` (알바가 같은 수요를 중복으로 가져가지 않게)
  - 운반: `Interactor` + `CarryStack`을 알바에게 그대로 붙이면 존 상호작용이 된다. **작업 고정 · 전환 쿨타임 · 가이드 화살표는 플레이어 전용** (`Interactor.ConfigureRules`를 알바에선 부르지 않음)
  - 돈: 고용금은 `Wallet.TrySpend`(보유 재화만). 시급은 `PartService.EndPart`의 `SettlementResult.Wages`(지금 0)에 넣으면 정산 팝업 · 차감까지 이어진다
  - 사무실 모듈(`StandardModules.BuildOffice`)에 고용 데스크 · 배치 현황판 자리를 만들어야 함 (계약 PC = 오른쪽 위, 저금통 = 왼쪽 위)
- 시작 전에 사용자(기획)에게 확인할 것: 고용 데스크 UI 여부(바로 고용이면 게이지만?), 배치 현황판 UI 형태, 고용 순서 · 최대 인원 표시 방식

### 5. 작업 규칙
- 매 단계: **시작 전에 질문해 확정 → 구현 → Play 테스트 → 문서 반영(GDD · 체크리스트 · TechStack · Wiki) → 커밋**
- 스크립트를 추가 · 삭제하거나 역할이 바뀌면 **같은 커밋에서 [Wiki](Wiki.md) 항목**(역할 · 동작 · 연결 · 주의)을 고친다
- 수치는 코드에 쓰지 않고 `Assets/Data`의 ScriptableObject에서 읽는다 (진입점 `GameDatabase`)
- 모듈 프리팹은 씬을 직접 참조하지 않는다 (`Instance` 또는 자체 등록 목록). 모듈 내용은 `StandardModules` 코드 → `Rebuild` 또는 프리팹에서 고친다
- 답변 · 문서는 한국어. 커밋은 요청할 때만 (푸시는 아직 한 번도 안 함)

M0 기반 ─▶ M1 이동·카메라 ─▶ M2 운반 코어 ─▶ M3 입고·보관 ─▶ M4 주문·수익 ★첫 플레이어블

        ┌──────────────────────────────────────────────────────────┘
        ▼
M5 성장·확장 ─▶ (M7 배치 개편 v0.3 ✓) ─▶ M5b 저금통·파트 정산 ─▶ M6 알바 ─▶ M8 Lv.1~11 콘텐츠 ─▶ M9 반품 ★1순위 완료

### 이 순서인 이유

1. **손맛을 가장 먼저 검증한다 (M1~M2).** 자동 집기·스택 연출이 재미없으면 그 위에 쌓는 모든 시스템이 의미가 없다. 박스 몇 개와 선반 하나만으로 바로 검증할 수 있다.
2. **돈이 들어오는 1사이클을 최대한 빨리 완성한다 (M3~M4).** 혼자서 하차 → 분류 → 피킹 → 상차 → 현금까지 돌아가야 이후 시스템(성장, 알바)을 붙였을 때 효과를 체감할 수 있다.
3. **성장(M5)을 알바(M6)보다 먼저 만든다.** 알바 고용은 구매 패드, 재화, 최대 인원(레벨) 위에서 동작한다. 부지 확장은 네비메시 재굽기와 묶여 있어서 알바 전에 구조를 잡아 두는 편이 낫다.
4. **저금통 · 파트 정산(M5b)을 알바(M6)보다 먼저 만든다.** 알바 시급이 파트 정산에서 빠져나가고, 고용금은 보유 재화에서 나간다.
5. **반품(M9)은 마지막이다.** Lv.11 전용이고, 다른 시스템을 모두 재사용한다.
6. **디버그 메뉴는 M0에서 만들고 계속 늘린다.** 재화·레벨·배속 치트가 없으면 M5 이후 테스트가 너무 느려진다.

### 공통 원칙

- 아트는 **임시 프리미티브**로 진행한다. 단, 테이프 색(품목 구분)은 처음부터 적용한다.
- 수치는 처음부터 **ScriptableObject**에서 읽는다 (코드에 숫자를 쓰지 않는다).
- 플레이어와 알바가 **같은 운반 컴포넌트**를 쓰게 만든다 (M2에서 설계 → M6에서 재사용).
