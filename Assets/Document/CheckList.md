**M20-3 모듈 회전 · 하차 모듈 이동** (GDD 4.4 · 7.1)
- 정해진 것: 하차 모듈은 **부지 테두리 칸에만**. 회전으로 트럭이 들어오는 변을 고르고, **진입 변이 부지 안쪽을 보는 회전 · 자리는 불가**(흔들림 + 사유). [회전] 90°씩, 옮길 수 있는 모듈 모두(하차 · 보관 · 반품), 팝업 닫을 때 반영, 비용 없음. 상차 · 사무실 · 쓰레기장은 그대로 못 옮김. 옮기거나 돌린 모듈 **위를 지나가는 벨트는 철거**(안내 · 전액 환불, M18-4 규칙에 회전 추가).
- 임시로 적어 둔 것(GDD 18장 64): 서 있던 트럭은 새 자리에 그대로 주차 · 상자 유지, 대기 줄은 서쪽 도로 그대로.
- **아직 물을 것**: 하차 2칸 묶인 배치(`In1` · `In2`, `SiteLayout` IsLinked)를 하나로 옮길지 칸마다인지 — 코드 구조를 본 뒤 질문.
- 코드 단서: `UI/ModulePanel`(Drop · Apply · `BeltsOnMoved`), `SiteLayout.GetRotation`, `SiteGrid`, `SiteWalls`(하차 칸 바깥 벽 판정 `module.rotation * Vector3.left`), `InboundBay` · `InboundQueue`(트럭이 모듈 바깥 가장자리에 나타나 후진).

**M20-4 벨트 자유 배치 · 통과 불가** (GDD 7.10)
- 정해진 것: 2m 격자 대신 **연속 배치**(점 맞춤 0.5m `임시`), 시설 · 존 **바로 옆 · 좁은 틈 허용**(겹칠 때만 막힘), 벨트는 플레이어 · 알바가 **못 지나감**(넘어가는 자리 없음), 저장 전 **길 막힘 검사 = 모든 상호작용 존 + 열린 칸(해금 발판 포함)**에 플레이어가 갈 수 있어야 함 → 막히면 [저장] 꺼짐 + `길이 막힙니다`. 재배치 · 회전은 길 검사 대신 위 철거 규칙.
- 상자 간격 2m · 속도 초당 2m는 그대로 `임시`. 코드: `UI/BeltPlacer`(칸 단위 `TileOf` · `SegmentFree` · `OverlapsSelf`), `Logistics/ConveyorBelt`.

**M20-5 벨트 스캔 구역** (GDD 7.2a · 7.10)
- 정해진 것: 하차 공간 → 스캔 팔레트 벨트의 한 지점에 스캔 구역, 벨트 옆 작업 존에 **플레이어 또는 하차 알바**가 서면 지점에 멈춘 상자를 **1개씩 1초** 스캔 → 그 상자만 팔레트로, 뒤 상자는 줄지어 대기. 스캔 속도는 플레이어 · 알바 같음.
- 임시(18장 68): 벨트당 1개 · ₩50, 사람 없음 · 정할 색 없음 = 대기, 하차 알바는 벨트 스캔 구역을 스캔 팔레트보다 먼저 잡음, 벨트 철거 때 같이 철거.

### 5. 작업 방식 · 금지
- 흐름: 사용자가 할 일을 주면 **질문(AskUserQuestion) → GDD · CL 작성 후 멈춤 → "시작" → 구현 → MCP Play 테스트 → 문서(CL · Wiki · GDD · ParameterList) → 한국어 보고**. 사용자 손 테스트 뒤 "커밋" 지시가 오면 커밋. push는 지시할 때만.
- 답변 · 문서 전부 한국어.
- **덮어쓰기 금지**: `EnsureAll(true)` · `Rebuild Standard Modules` · `Apply M6 Staff` · `Apply Character Models` · Build Site 전체 · `StandardModules`의 `overwrite`(특히 `ShelfPrefab(overwrite)`는 손으로 고친 `Shelf.prefab`을 덮음). 프리팹을 고칠 땐 MCP `execute_code`로 `PrefabUtility.LoadPrefabContents` → 수정 → 저장 (M19-1 · M20-2 방식).
- `CashFlyConfig` · `StampConfig` 값은 사용자가 고친 값 — 되돌리지 않는다.
- 커밋 전 폰트 `LiberationSans SDF - Fallback.asset`은 `git checkout --`. `Assets/Screenshots`는 **내가 만든 파일만** 지운다(main에 `qa_*.png` 커밋돼 있음).
- MCP 테스트 팁: Play 직후 `StartSequence.Instance.Skip()` + `SiteGrid.Unlock(id)`로 모듈 해금(id: `Office` · `Trash` · `In1` · `In2` · `Out1~3` · `StoreA1` · `StoreA2` · `StoreB~D` · `Ret1~2` · 스캔). 플레이어 이동은 `CharacterController` 끄고 옮긴 뒤 켬, 플레이어 = `RestrictToTarget`이 false인 `Interactor`. `execute_code`는 codedom(C# 6)이라 `Object`는 `UnityEngine.Object`로. 시간 측정은 `DOVirtual.DelayedCall` + `Debug.Log` 후 콘솔 읽기. `Assembly-CSharp.dll` 복사 실패는 다시 컴파일하면 됨.

### 이 순서인 이유

1. **손맛을 가장 먼저 검증한다 (M1~M2).** 자동 집기·스택 연출이 재미없으면 그 위에 쌓는 모든 시스템이 의미가 없다. 박스 몇 개와 선반 하나만으로 바로 검증할 수 있다.
2. **돈이 들어오는 1사이클을 최대한 빨리 완성한다 (M3~M4).** 혼자서 하차 → 분류 → 피킹 → 상차 → 현금까지 돌아가야 이후 시스템(성장, 알바)을 붙였을 때 효과를 체감할 수 있다.
3. **성장(M5)을 알바(M6)보다 먼저 만든다.** 알바 고용은 구매 패드, 재화, 최대 인원(레벨) 위에서 동작한다. 부지 확장은 네비메시 재굽기와 묶여 있어서 알바 전에 구조를 잡아 두는 편이 낫다.
4. **저금통 · 파트 정산(M5b)을 알바(M6)보다 먼저 만든다.** 알바 시급이 파트 정산에서 빠져나가고, 고용금은 보유 재화에서 나간다.
5. **반품(M9)은 마지막이다.** Lv.11 전용이고, 다른 시스템을 모두 재사용한다.
6. **디버그 메뉴는 M0에서 만들고 계속 늘린다.** 재화·레벨·배속 치트가 없으면 M5 이후 테스트가 너무 느려진다.

### 공통 원칙

- 아트는 **임시 프리미티브**로 진행한다. 단, 테이프 색(품목 구분)은 처음부터 적용한다.
- 수치는 처음부터 **ScriptableObject**에서 읽는다 (코드에 숫자를 쓰지 않는다).
- 플레이어와 알바가 **같은 운반 컴포넌트**를 쓰게 만든다 (M2에서 설계 → M6에서 재사용).
